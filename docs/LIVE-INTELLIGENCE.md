# Live Intelligence v1 — local monitoring

Intel → Live Intelligence accepts a local JSON report (maximum 64 KiB). UI labels are available in 16 locales; native visual and linguistic review remains incomplete. No network transport or account access. Data is localStorage only, not a public GitHub artifact. After 120 seconds the current state is unknown. Never commit real reports.

Windows: review tools/Export-LiveSnapshot.ps1, run it in PowerShell without administrator elevation; optionally use -Watch for 15-second collection (Ctrl+C stops). Default output is %LOCALAPPDATA%/VEKAID/live-snapshot.json. Transfer a report privately to iPhone and import it. Exact process names are weak observations, not proof of availability; wrapped CLI processes may not be detected. No quota counters are collected by this script. No auto-start or installation.

Integration: reuse existing Windows diagnostics and coordinator PR #64 duplicate-key rejection; do not alter coordinator availability format or equate provider quota with role readiness. Future adapters: verify installed Claude Statusline schema and Codex App Server account/rateLimits/read; normalize each usage window with source and timestamp, without transmitting auth tokens or prompting models. ChatGPT Images exact consumer quota remains unknown absent supported source. WanGP progress requires existing job events. Private authenticated HTTPS transport and native Safari tests required before claiming live sync. Do not publish telemetry to GitHub Pages or expose a local server to the internet. No paid services.

Release gate: test imports, malformed inputs, stale state, all locales, offline cache, data export/privacy, existing workflows and native mobile navigation. Command Deck prepares a local request only; it sends no command. The mobile layout separates status, providers, hardware, import and request preparation. Native Safari validation remains required.

## Private bridge (candidate)

The read-only bridge serves the existing snapshot file on 127.0.0.1:8765. It requires a session bearer token and restricts browser origins to the production GitHub Pages origin. It filters provider and hardware fields, limits reports to 64 KiB, rejects duplicate JSON keys, and never accepts commands. The browser accepts HTTPS endpoints on a private Tailscale DNS name, rejects redirects, polls every 15 seconds while the screen is open, and retains the latest valid observation locally. The token remains in memory for the current browser document. Reopening the monitor resumes polling; reloading the document or explicitly disconnecting clears the pairing. Restarting the bridge requires the same token or a new pairing. Do not share the token in screenshots or commits. Optional vram_percent and storage_percent fields are normalized percentages; The canonical Windows collector also emits vram_used_mib/vram_total_mib and storage_free_bytes/storage_total_bytes; valid pairs are normalized to usage percentages. No quota adapter is claimed by the bridge.

Suggested private network: Tailscale Personal (free for personal use) and **Serve**, never Funnel. Requires user-approved installation and sign-in on Windows and iPhone, plus HTTPS configuration. Restrict tailnet access to authorized devices. Official instructions: https://tailscale.com/docs/features/tailscale-serve and https://tailscale.com/docs/reference/tailscale-cli/serve . An administrator console may be needed for Serve on Windows; do not change firewall permissions or expose public ports. HTTPS may publish machine DNS names in certificate transparency logs; choose non-identifying names.

On Windows, after the updated code is available, run the existing collector in a separate non-admin PowerShell: `powershell -NoProfile -File tools/Export-LiveSnapshot.ps1 -Watch` (review local execution policy; do not bypass it). Then from the repository run `python tools/live_bridge.py --snapshot "$env:LOCALAPPDATA\\VEKAID\\live-snapshot.json"`. Copy the generated token privately. With the private network already configured, use `tailscale serve --bg http://127.0.0.1:8765` from the appropriate administrator terminal and use the reported private HTTPS address. In VEKAID > Intel > Live Intelligence > Private connection, enter that address and the token. Native Safari cross-origin behavior, authorization, and real Windows snapshots must be verified on the actual devices. If private access fails, preserve the last report; do not switch to public Funnel or disable browser security. Stop Serve and the bridge after testing if not needed.

Canonical Windows collector: https://github.com/Vekaid-T-Engine/Vekaid-AI-Ecosystem/tree/feature/windows-live-snapshot . It supports -CodexQuota, which reads the authenticated account via the official App Server and selects the most consumed active window. This is not a combined quota. Use the canonical collector in preference to the provisional exporter. The PC and iPhone have joined the private network, but the HTTPS service and native Safari round trip require verification with both devices online.

## Optional session supervisor

Review tools/Start-LiveSession.ps1 before executing on Windows. It starts the canonical collector and bridge as current-user jobs, stores a pairing secret encrypted by Windows DPAPI in the current user's local application data, and stops its jobs on exit. It does not install a startup task or configure Tailscale Serve. Stop any previous collector/bridge instance first, use the canonical collector's full local path and -CodexQuota if authorized. The supervisor is not yet Windows-tested. Do not enable automatic logon startup until a manual end-to-end session and token handling are validated. Rotate pairing credentials by stopping the supervisor and replacing the local encrypted token, then pair again. Never commit local data or credentials. HTTPS Serve must remain tailnet-only. 

The frontend permits only HTTPS *.ts.net in addition to its own origin through CSP. The client further checks the endpoint scheme and host, refuses redirects, and does not send credentials as cookies. The mobile browser audit now includes the monitor at widths 320, 390 and 430. These checks do not replace the native iPhone HTTPS round trip.
