# VEKAID — Product quality standard

Applies to every future change. Preserve the existing monochrome identity, V mark, particle field, launch motion and Intelligence/Missions navigation unless explicitly approved. No new paid services. No personal data or secrets in this public repository.

## Workflow
1. Research relevant professional references and verify claims.
2. Define the user problem, acceptance criteria and non-regression scenarios.
3. Compare alternatives; prefer the smallest effective change.
4. Implement maintainable code; remove superseded code only after checking dependencies.
5. Review motion, hierarchy, typography, spacing and mobile ergonomics.
6. Red-team security, imports, storage, error handling and data integrity.
7. Score the release using the rubric below, with evidence and unknowns.
8. Run tests, verify deployment and validate on real iPhone Safari/PWA.

## Rubric (50 points)
Score each criterion only with evidence; untested means unverified, not passed.
- Engineering (5 each): real functionality, responsive behavior, security/privacy, performance, accessibility/reliability.
- Aesthetics (2 each): composition/hierarchy, typography, art direction, visual assets, consistency/finish.
- Creativity (3 each): original useful concept, brand identity, meaningful motion, visual narrative, memorable experience.
Target 45/50; never invent a score or claim independent model comparison without performing it.

## Blocking checks
- Data loss, misleading metrics, critical security issues, broken essential actions or major mobile regressions block release regardless of score.
- Check safe areas, bottom dock, horizontal overflow, double-tap behavior, keyboard access, reduced motion, launch flash, scroll restoration and transitions.
- Preserve existing IndexedDB/localStorage data; test migrations and backups.
- Distinguish empty, loading, error and verified states; do not invent skills or missions.
- Check cache/version consistency, obsolete assets and duplicate handlers; no blind deletion.
- Record actual test commands/results, unresolved issues, commit and deployment status.
- Device-specific claims require device testing; distinguish automated checks from real-device checks.

## Release record
Change / rationale / evidence / rubric / blockers / deployment / rollback.

## Permanent video-to-workflow procedure
Extract source, date, observable claim, applicability, verification, decision and regression test. Research -> Art Direction -> Creative Exploration -> Engineering -> Motion Design -> Red Team -> Taste Review -> Quality Gate. Preserve brand-specific visual language; avoid generic repeated cards, decorative icons and gratuitous motion. Review actual screenshots at mobile and desktop sizes. Track time, cost and tokens only when measured.

## Role-based local routing (experimental)
Coordinator, research, engineering, design, security and QA roles receive bounded tickets and evidence requirements. Local Ollama output is a draft, verified against source before use. Benchmark small models in isolation before adoption; no paid API, no exposed local endpoint, no installation without approval. No claimed savings without measurements.

## Data engineering gate
Apply [Data Engineering & System Design](docs/data-engineering-quality-gate.md) to every architecture. The CI regression suite must preserve Academy lesson positions, verify feed validation, coherent snapshot exports and cache version alignment. Restore and actual device tests remain separate release requirements.

## Advanced UI Finishing & Visual Precision
Source: user-supplied video, “10 Niche Design Hacks”. Review concentric radii, alpha borders, OKLCH palettes and gradients, matched icon weights, masked edges, blurred icon swaps, dark-mode depth, dynamic viewport, multiply blending. Apply selectively: preserve each product's identity, contrast and keyboard focus; use dynamic viewport with fallback; respect reduced motion. Never mask actionable content, animate icons without a meaningful state change, or multiply-blend actual food photography. Test narrow screens, safe areas, keyboard, reduced motion and real Safari before claiming device validation. VEKAID applies subtle alpha borders, depth, consistent icons, dock geometry and dynamic viewport; other techniques conditional.

## Anti-generic design review (19-point video checklist)
Review gradient blobs, circle icons, default purple, floating 3D, identical feature cards, stock team photos, rainbow accents, fake product photos, buzzwords, generic testimonials, three-word headlines, repetitive FAQs, bento grids, cookie-cutter flows, decorative emojis, vague CTAs, dead links, excessive soft corners, and missing personality. These are review prompts, not blanket bans. Keep functional cards, existing VEKAID radar and motion, authentic imagery, accessible geometry and clear navigation. Require meaningful copy, real evidence and tested destinations. Never invent testimonials. Review screenshots before approving visual changes.

## Internationalization
Offline interface localization: French, English, German, Simplified Chinese. Preserve original user data and lesson IDs; explicitly disclose untranslated learning/news/legacy content. Test locale persistence, overflow, fallback, offline reload and all language switches before claiming full localization. No external translation API.

## Locale coverage follow-up
V23.24 expands the four offline language packs to cover the observed legacy home dashboard, project descriptions and common availability states. Dynamic counters are translated without changing underlying data. Full legacy, Academy and news localization is not yet complete. Do not advertise a language as fully supported until coverage and real-device tests pass. A language-name library alone does not translate text; additional packs must contain reviewed translations.
